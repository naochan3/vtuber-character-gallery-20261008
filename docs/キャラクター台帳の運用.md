# キャラクター台帳の運用

採用502の見た目を固定し、表情・動作・掛け合い・制作条件を同じ番号で参照する。今回の作業は既存の静的な比較サイトへの通常の機能追加。追加のサーバー契約や外部データベースの作成は行わない。

## 正本と確定状態

正本は `data/characters/marble-502.json`。採用済み、設定案、制作案、未確定を項目ごとに区別する。採用済みはユーザーの指定に基づく見た目と目的。今回の詳細な性格や台詞は設定案として編集できる。名前や正確な年齢・身長は未確定。

設定画像は参照資料であり、画像内の誤字や生成側が加えた数字で正本を更新しない。実際の分割済み原画、音声、動画、動作モデルはこの作業には含まれない。

## 保存

- 内部データベース：`.local/characters.sqlite3`。正本から生成し、公開フォルダーとGit管理から除外する。
- 設定番号、対象、種類、確定状態で検索できる。変更前の正本を履歴テーブルに保存し、同じ内容の再構築では履歴を増やさない。
- 公開ページ：`site/character-502.html`。公開用に出力した現在の設定だけを読む。内部データベースや更新履歴への外部書き込み機能は持たない。
- 更新は正本へ行い、公開ページと内部データベースを再生成する。生成物を別々に手編集しない。

## 情報を引き出す

公開ページで「驚く」「メモ」「猫」や `E10` などの番号を検索し、種類と対象で絞る。個別項目は直接リンクとコピーに対応。制作指示のコピーには採用済みの固定条件が付く。

内部台帳の操作例：

```powershell
python scripts/character_db.py build
python scripts/character_db.py search 驚く --actor 女の子
python scripts/character_db.py search メモ
python scripts/character_db.py search 502 --status 採用済み
python scripts/character_db.py prompt E10
```

名前が決まったら `aliases` に追加する。表情を増やすときは既存番号を使い回さず追加し、対応シートの `recordIds` と双方向に対応させる。

## 今回の完了条件

502の正本を保持し、詳細資料10枚と設定項目を保存する。検索・対象別表示・確定状態・個別リンク・コピーが使えること、画像の保存内容が一致すること、過去の比較候補が変わっていないことを確認する。内部データベースの再構築と履歴保持、引用符や検索記号を含む入力での検索も確認する。
